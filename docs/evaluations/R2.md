## Pass 1 — findings

Five findings. Three blocking, two non-blocking.

- **F1 — REQ-TODO-3 ambiguity around "today" semantics.** The mock shows `Today, 9 May` and `3 of 7 complete` in the page header. The original requirement said the count was "for the current day", which conflicts with the rest of the doc treating the list as the user's full to-do set. Implementer can't tell whether the list is date-scoped. **Blocking.**
- **F2 — Missing requirement for the activity strip on the detail screen.** The mock shows `Created` and `Marked complete` entries; the out-of-scope list explicitly preserves "the simple activity strip in the detail mock", but no positive requirement formalizes it. Without it, an implementer can omit the strip and pass evaluation. **Blocking.**
- **F3 — Missing requirement for to-do list ordering.** Mocks show a particular order; without a deterministic rule, two implementations can both pass while showing different orders, which breaks ATDD. **Blocking.**
- **F4 — Password policy referenced but not defined.** REQ-AUTH-1 / REQ-AUTH-4 / REQ-ACCT-3 say "meeting policy"; only REQ-AUTH-1 AC3 implies length ≥ 12. The policy needs its own requirement so test code can lift it directly. **Non-blocking** (doc is functional without it but ambiguous).
- **F5 — REQ-ACCT-2 email-change verification has no mock support.** The original wording implied a verification screen / flow not present in the accepted mocks. Either add a screen (regresses D2) or constrain the UX to the existing profile surface. **Non-blocking** (clarification, not a contradiction).

### Fixes applied between Pass 1 and Pass 2

- REQ-TODO-3 reworded to clarify the list shows ALL the user's to-dos (not date-scoped), the count is overall, and a new AC4 specifies deterministic server-side ordering: `due_date` ascending nulls last, then `created_at` descending.
- New REQ-TODO-3a added: page-header date label is informational only.
- New REQ-TODO-8 added: activity strip with `Created` and (when applicable) `Marked complete` entries; explicit timestamp formatting; explicit non-goals (no comments, no full audit log).
- New REQ-AUTH-7 added: password policy is `length ≥ 12` and `length ≤ 256`, with no further complexity rules. Length is the strength lever.
- REQ-ACCT-2 reworded: email-change uses an inline banner on the existing profile surface (no new mock); verification email goes through the no-op logging service in v1; original email remains the sign-in identifier until verified.
- Doc status line updated to `approved (R2 pass 2 clean)`.
