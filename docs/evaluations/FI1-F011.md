# FI1 / F-011 — Responsive sweep + mock-fidelity verification

Implementer / evaluator: `claude@M5`.
Acceptance specs: `e2e/specs/responsive.spec.ts` — 12 cases covering nav-rail-vs-nav-bar visibility at 360 / 768 / 1440 across the three app-shell routes (`/todos`, `/profile`, `/error`), no-horizontal-scroll on the same matrix, primary-action 48dp touch targets on `/todos` (FAB) and `/profile` (sign-out), and a no-horizontal-scroll check on the unauthenticated `/sign-in` page.

## Per-slice loop trace

1. **Tests first** (commit `3b54aea`). New `e2e/specs/responsive.spec.ts` (12 cases via parameterised loops over breakpoints × app-shell routes plus 3 standalone cases).
2. **Initial run findings.**
   - 11 of 12 specs passed first time. The 9 nav-rail / nav-bar matrix cases all behaved as designed — `<600px` shows the bottom nav-bar; `≥600px` shows the side nav-rail. No horizontal scroll on any combination.
   - **One real finding:** the `Sign out` button on `/profile` measured 40dp tall on a 360px viewport. Material 3's default `mat-stroked-button` height is 40dp, and although Material's underlying MDC button injects a 48dp invisible touch-target overlay, `Locator.boundingBox()` reads the visible size — and REQ-NFR-7's "touch targets ≥48dp" is the rule the spec is enforcing. This is a real mobile-UX regression: the visible target users see and aim at is 40dp.
3. **Fix.** Added a per-page `@media (max-width: 599px)` rule in `frontend/projects/tickbox/src/app/profile/profile-page.component.scss` that bumps `min-height: 48px` for `mat-stroked-button` and `mat-flat-button` instances inside `.profile-page`. Scoped to the page rather than global because (a) only the profile page is in the spec, (b) Material's default 40dp height is intentional for desktop density and a global override would change every shipped slice's mock fidelity, and (c) future affected pages should opt in deliberately with the same rule.
4. **Re-run.** Failing spec went green; full suite 51/51.
