# D2 — Evaluate HTML mocks

Evaluator: `claude@M5`. Evaluation passes against the D2 rubric (9 criteria) for every screen in `./mocks/`. Fix-on-find applied between passes.

Screens reviewed: `index.html`, `sign-in.html`, `sign-up.html`, `password-reset.html`, `todos.html`, `todo-detail.html`, `todos-empty.html`, `profile.html`, `error.html`.

## Pass 1 — findings

Checked each criterion across all 9 screens.

1. **Material 3 adherence.** Pass. Tokens for color (primary / secondary / surface / on-surface / containers / outline / error and inverse roles), full type scale (display/headline/title/body/label × L/M/S), elevation levels 0–5, shape scale (none → full), and component anatomy (top app bar, navigation rail + bottom bar, FAB extended, cards, chips, snackbar, text fields, list items, avatar) are all present. Material Symbols icon font wired via Google Fonts CDN.
2. **Radically simple.** Pass. One stylesheet, three nav destinations (To-dos / Inbox / Profile), one entity (Todo) with the only two states the idea requires (Incomplete / Complete). No decorative chrome.
3. **Great UX.** Pass. Each screen has a single dominant primary action — filled button on auth screens, extended FAB on the list, filled "Save" on detail, prominent CTA in empty / error states.
4. **Responsive.** Pass. Mobile-first base styles, breakpoints at 600px (rail appears) and 1240px (rail expands to labelled). Test widths 360 / 768 / 1440 fall into mobile / tablet-rail / desktop-expanded-rail respectively. No horizontal scroll, no clipped content.
5. **Static + hard-coded.** Pass. `grep` finds no `fetch(`, `XMLHttpRequest`, `localStorage`, `sessionStorage`, `.json` loading, or dynamic imports. The only inline JS is single-line `onsubmit` navigation handlers, which is permitted by D1 ("no JavaScript behavior beyond what is needed for navigation").
6. **BEM naming.** **FAIL** (then fixed). Two issues found:
   - Typography utility classes (`type-display-l`, `type-headline-s`, `type-title-m`, `type-body-m`, etc.) used a single-segment `type-*` form that does not conform to Block / Block__Element / Block--Modifier. Fixed by renaming to a `.text` block with `.text--<scale>` modifiers (e.g., `text text--body-medium`) and adding a `.text--on-surface-variant` colour modifier.
   - In `error.html`, the empty-state icon's error tint was applied via inline `style=` overriding `--md-sys-color` vars. Fixed by adding an `empty-state__icon--error` BEM modifier in the stylesheet and using it on the markup.
7. **Coverage vs idea.** Pass. The idea (`docs/idea.md`) calls for a radically simple to-do app with two states. Mocks cover: sign-in, sign-up, password-reset (unauthenticated); to-dos list (with both states + filter chips), to-do detail/edit, empty state, profile / sign-out, and error state.
8. **Mobile-first appearance.** Pass. Baseline rules target small viewports; touch targets ≥48dp on the bottom nav (80px tall), top app bar actions (48px), text fields (56px), list items (≥48px effective). Type scale legible at 360px; spacing (4dp grid) is comfortable, not cramped.
9. **No build step.** Pass. Each `.html` opens directly via `file://`. Only external resources are the shared `styles.css`, the Google Fonts CDN for Material Symbols, and the Roboto Flex font CDN — all standard CDN links, no bundler.

### Fixes applied between Pass 1 and Pass 2

- Stylesheet: replaced `.type-*` utility classes with a BEM `.text` block + `.text--<scale>` and `.text--on-surface-variant` modifiers.
- Stylesheet: added `.empty-state__icon--error` modifier.
- HTML: updated `profile.html`, `todos.html`, `todo-detail.html` to use the new `text` block / modifiers, removing inline colour overrides where the modifier covers them.
- HTML: replaced inline-style error tint in `error.html` with the new modifier.
