1. **Tests first** (commit `cd6ac04`). New `OidcEnabledFactory` (sets `Oidc:Enabled=true` and registers a `TestOidcClient`); the disabled-test reuses the default `TickboxApiFactory`. Compile-red until the slice landed.
2. **Implementation:**
   - **Domain:** `OidcAuthorizationRequest { State (PK), CodeVerifier, ExpiresAt }`.
   - **Application:**
     - `Auth.Oidc.OidcUserInfo` (`Subject`, `Email`, `DisplayName`).
     - `Auth.Oidc.IOidcConfiguration` interface (read-only view onto the OIDC settings the Application layer needs).
     - `Common.IOidcClient` interface — single method `ExchangeCodeAsync(code, codeVerifier, redirectUri)` returning `OidcUserInfo`.
     - `Auth.Oidc.BeginOidcSignInQuery` + handler: generates a 64-byte verifier, sha256/base64-url challenge, 32-byte state, persists `(state → verifier)` with a 5-minute TTL, returns the IdP authorization URL with `client_id`, `redirect_uri`, `response_type=code`, `scope`, `state`, `code_challenge`, `code_challenge_method=S256`.
     - `Auth.Oidc.CompleteOidcSignInCommand` + validator + handler: looks up the stored state row; rejects (400) if missing/expired; calls `IOidcClient.ExchangeCodeAsync(code, verifier, redirectUri)`; on first sign-in for the email, creates a `User` with `PasswordHash = null` and attaches the seeded `User` role; deletes the state row regardless; issues access + refresh tokens; returns `AuthenticationOutcome`.
   - **Infrastructure:**
     - `OidcOptions` (Enabled / Authority / ClientId / ClientSecret / RedirectUri / Scopes).
     - `OidcConfigurationAdapter : IOidcConfiguration` reading `IOptions<OidcOptions>`.
     - `OidcClient : IOidcClient` — real implementation using a typed `HttpClient` to POST `authorization_code` to `<authority>/token`, then GET `<authority>/userinfo` with the access token, mapping to `OidcUserInfo`.
     - `DisabledOidcClient : IOidcClient` — registered when `Oidc:Enabled = false` so the MediatR handler can be constructed at startup without conditional registration of the handler itself; throws `InvalidOperationException` if ever called (the controller short-circuits with 404 first).
     - `AppDbContext` configures the `OidcAuthorizationRequests` table (state as PK, max-lengths).
     - `DependencyInjection` registers `IOidcConfiguration` always, then conditionally registers `OidcClient` (typed `HttpClient`) when enabled or `DisabledOidcClient` when disabled.
   - **Migration #009 `AddOidcAuthorizationRequests`** — table ships unconditionally per BT2 F1 ruling.
   - **Api:** `AuthController` adds `GET /api/auth/oidc/authorize` and `POST /api/auth/oidc/callback`. Both `[AllowAnonymous]`. Both check `_oidc.Enabled` first and return 404 if disabled, satisfying REQ-AUTH-3 AC2 and the BT1 explicit test. New HTTP request DTO `OidcCallbackRequest`.
   - **Tests:** `TestOidcClient` returns canned `OidcUserInfo`; `OidcEnabledFactory` wires it up and enables the flag.
