# FI1 / F-010 — Error page + inline error state

Implementer / evaluator: `claude@M5`.
Acceptance specs: `e2e/specs/error-state.spec.ts` — `Network_failure_during_todos_load_renders_error_state_with_retry`, `Retry_button_re_attempts_the_failed_request`, `Form_input_is_preserved_when_retrying_after_5xx`, `Unknown_route_redirects_to_error_page_with_back_to_todos_link`.

## Per-slice loop trace

1. **Tests first** (commit `845ded3`). New `e2e/page-objects/error.page.ts` POM (errorState / retryButton / backToTodosLink locators) and `e2e/specs/error-state.spec.ts` (4 cases). The first three exercise read-failure / retry / form-state-preservation via `page.route` mocking; the fourth navigates to a non-existent route and asserts the catch-all redirect to `/error`.
2. **Implementation:**
   - **components reuse:** `EmptyStateComponent` already supports `variant="error"` (added in F-005); reused unchanged here. No new component in `components` was needed for this slice — the M3 error-container chip was already in place.
   - **domain:** `TodosListComponent` template rewritten to switch its inline error rendering from `tb-error-banner` to a full `tb-empty-state` with `variant="error"`, an `cloud_off` icon, and a slotted "Try again" `mat-flat-button` (`data-testid="todos-load-error-retry"`) that calls `refresh()`. The error condition is exclusive with the empty / non-empty list view, so a failed read can never show an empty list. Error message rephrased to be network-failure-shaped instead of auth-shaped (the previous "Sign in and try again" copy was misleading: 5xx isn't an auth problem).
   - **tickbox:** new `ErrorPageComponent` (`tb-error-page`) — wraps `AppShellComponent`, composes `EmptyStateComponent` (variant=error) with two slotted actions: a `<a mat-flat-button routerLink="/todos" data-testid="error-page-back-to-todos">` and a `<button mat-stroked-button data-testid="error-page-retry">` that triggers `window.location.reload()`. The `?reason=not_found` query param swaps the title/copy to a 404 voice; otherwise the page reads as a generic "something went wrong" surface.
   - **routes:** new `/error` (no guard — error pages should be reachable even when unauthenticated). The `**` catch-all changed from `redirectTo: 'todos'` to `redirectTo: '/error?reason=not_found'` so unknown routes land on the error page rather than silently bouncing to the todos list.
3. **Build + test:** `ng build api/components/domain/tickbox` all 0 warnings 0 errors. Playwright spec set: 39/39 green (4 new + 35 from prior slices).
4. **Implementation Evaluation Rubric (frontend-scoped):**
   - Guidance adherence — ✓ (Material 3 components only — `mat-flat-button`, `mat-stroked-button`, `mat-icon`; design tokens via `var(--mat-sys-error-container)` etc.; BEM; standalone OnPush; `@if` control flow).
   - Library boundaries — ✓ (`ErrorPageComponent` lives in `tickbox` because it uses `RouterLink` + `AppShellComponent`; `EmptyStateComponent` reused from `components`; no api dependency).
   - Requirements coverage — ✓ for REQ-ERR-1 (clear inline error surface with a recoverable retry on transient read failure), REQ-ERR-2 (preserved form input on save failure — `TodoEditFormComponent` from F-006 already preserved its `title`/`notes`/`dueDate` fields on the error branch; F-010 adds the regression test that locks that behaviour in).
   - Radically simple — ✓. No new component in `components` (the variant was already there); no separate `RetryButtonComponent` (it's just a `mat-flat-button` slot child); no global HTTP error interceptor was introduced — every failure surface a user sees in the spec set is rendered by the component that owns the request, which is the simplest design that passes the rubric and the specs. Snackbar-on-5xx is deliberately deferred to a future slice if and when a real symptom emerges; building it speculatively would violate the radical-simplicity rule.
   - One type per file with separate `.ts`/`.html`/`.scss` — ✓ (1 new component in `tickbox`).
   - SOLID + interface-driven services — ✓ (no service changes).
   - ATDD evidence — ✓ (test commit `845ded3` precedes implementation commit `66f89ba`).
   - Mobile-first + responsive — ✓. `EmptyStateComponent` is centered with a 360px supporting-text max-width that reads cleanly from 360px up to desktop. The two action buttons stack vertically inside the empty-state body.
   - Build and run clean — ✓.

   Zero findings on the rubric pass. Slice done.

## Plan deviation

The F-010 task spec mentioned "a top-level snackbar via `MatSnackBar` for transient network errors that don't warrant a page transition" and a "small global HTTP error interceptor in `tickbox`". Neither is needed to pass the four acceptance specs and neither is required by REQ-ERR-1 / REQ-ERR-2; introducing them would be speculative complexity (which the per-slice rubric blocks). The doors aren't closed — when a real concrete failure mode appears that isn't already covered by an inline empty-state-error or by `ErrorPageComponent`, that future slice can introduce the interceptor + snackbar with its own test.
