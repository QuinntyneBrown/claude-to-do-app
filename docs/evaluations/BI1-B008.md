## Per-slice loop trace

1. **Tests first** (commit `ee3ffd9`). Tests reference `PUT /api/account/password`, the per-session cookie behaviour ("revoke other sessions only" depends on the controller forwarding the caller's refresh-token cookie to the handler), and audit-event side-effects.
2. **Implementation:**
   - **Application:**
     - `Account.ChangePassword.ChangePasswordCommand(CurrentPassword, NewPassword, CallerRefreshToken?)`. The `CallerRefreshToken` is the plaintext value from the request cookie; the handler hashes it to identify "this session" so it does NOT get revoked.
     - `ChangePasswordCommandValidator` — `CurrentPassword NotEmpty`; `NewPassword 12–256` (REQ-AUTH-7); `NewPassword != CurrentPassword`.
     - `ChangePasswordCommandHandler`:
       - On wrong current → write `SignInFailed` audit (with `Detail = "Change password — wrong current."`), throw `ValidationFailureException` → 400.
       - On success → update `User.PasswordHash` (bcrypt re-hash), revoke ALL other unrevoked `RefreshToken` rows for the user where `TokenHash != Hash(CallerRefreshToken)`, write `PasswordChanged` audit. Per-user isolation via `ICurrentUserService`.
   - **Api:** `AccountController.ChangePassword` (`PUT /api/account/password`) reads the refresh cookie via the existing `RefreshTokenCookie.Read` helper and forwards it on the command. Returns 204 on success. New transport DTO `ChangePasswordRequest`.
3. **Build + test:** `dotnet build -warnaserror` 0/0; `dotnet test` 26/26 green (3 new + 23 pre-existing).
