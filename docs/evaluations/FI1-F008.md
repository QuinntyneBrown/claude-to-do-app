Implementer / evaluator: `claude@M5`.
Acceptance specs: `e2e/specs/profile-email-change.spec.ts` — `Request_email_change_renders_pending_banner`, `Cancel_email_change_clears_pending_banner`, `Confirm_email_change_with_valid_token_swaps_login_email`, `Confirm_email_change_with_expired_token_shows_inline_error_and_link_to_sign_in`.

## Per-slice loop trace

1. **Tests first** (commit `121ebe0`). New `e2e/page-objects/confirm-email-change.page.ts` POM (status / errorMessage / signInLink locators); extended `profile.page.ts` with `emailChangeInput`, `emailChangeSubmit`, `emailChangeError`, `emailChangeBanner`, `emailChangeBannerPending`, `emailChangeBannerCancel`. `e2e/specs/profile-email-change.spec.ts` (4 cases).
2. **Implementation:**
   - **api:** new `RequestEmailChangeRequest` and `ConfirmEmailChangeRequest` types. `IAccountService` extended with `requestEmailChange`, `confirmEmailChange`, `cancelEmailChange` (all returning `MyProfile` since the backend echoes the canonical profile after each mutation). Concrete `AccountService` POSTs `/api/account/email-change/request`, POSTs `/api/account/email-change/confirm`, DELETEs `/api/account/email-change` (B-007).
   - **domain:**
     - `EmailChangeFormComponent` (`tb-email-change-form`) — single email input + submit. On success emits `(requested)` with the updated `MyProfile` (which now carries `pendingEmail`).
     - `EmailChangeBannerComponent` (`tb-email-change-banner`) — M3 secondary-container surface, displays the pending email + a "Cancel" button. Cancel calls `IAccountService.cancelEmailChange` and emits `(cancelled)` with the updated profile.
   - **tickbox:**
     - `ProfilePageComponent` extended: renders the banner above the sections when `profile.pendingEmail !== null`, exposes the change form in a new "Email address" section, and routes both `(requested)` and `(cancelled)` events through a single `onProfileChanged` handler that re-sets the profile signal so every dependent view (summary + banner visibility) refreshes from one source of truth.
     - `ConfirmEmailChangePageComponent` (`tb-confirm-email-change-page`) — minimal route handler that reads `?token=` from the query string in `ngOnInit` and calls `IAccountService.confirmEmailChange`. On success it navigates to `/profile`. On 4xx it shows an inline `tb-error-banner` and a "Back to sign in" `<a mat-flat-button routerLink="/sign-in">`.
     - **Route note:** `/email-change/confirm` is intentionally **not** wrapped in `authGuard`. The token in the URL is the auth for that operation, and an unauthenticated user landing on the confirm link from their email must still be able to render the page (and see the error if the token is expired).
   - **routes:** `/email-change/confirm` added (no guard).
3. **Build + test:** `ng build api/components/domain/tickbox` all 0 warnings 0 errors. Playwright spec set: 33/33 green (4 new + 29 from prior slices).
