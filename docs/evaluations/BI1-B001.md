2. **Implementation:**
   - **Domain:** `Role`, `UserRole`, `KnownRoles` (constants + the seeded `User` role's GUID). One type per file. `User.PasswordHash` is now nullable (per BP plan §2 — needed for B-005's OIDC-only accounts).
   - **Application:** `IAppDbContext` exposes `Roles` and `UserRoles` `DbSet`s. `IJwtTokenService.CreateAccessToken` now takes `IReadOnlyCollection<string> roles`. `RegisterUserCommandHandler` inserts a `UserRole` row attaching the seeded `User` role and issues a JWT carrying the role claim. `SignInUserCommandHandler` reads the user's roles from DB and emits them in the JWT, plus handles `null` `PasswordHash` as a 401-generic (forward fix from BP2 F3 — pulled into this slice because the schema change lands here).
   - **Infrastructure:** `AppDbContext` configures `Roles` (unique-name index, `HasData` seed for `User`), `UserRoles` (composite key, cascade by user). `JwtTokenService` writes `ClaimTypes.Role` for every supplied role. `Users.PasswordHash` is now `HasMaxLength(256)` without `IsRequired()`.
   - **Migration #002 `AddRolesAndUserRoles`:** creates `Roles` + `UserRoles` tables, seeds the `User` role, and makes `Users.PasswordHash` nullable.
   - **Api:** `TodosController` is now `[Authorize(Roles = "User")]` instead of `[Authorize]`.
   - **Tests:** `TickboxApiFactory.EnsureSeeded()` adds the seeded role to the InMemory DB on first client request — `HasData` doesn't run for the InMemory provider, so this mirrors what the relational migration does for production.
